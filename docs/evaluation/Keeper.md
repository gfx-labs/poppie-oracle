# Keeper prototype: evaluation findings

*oracleSystem branch `v2`, 2026-11-10 to 11-16. The keeper design is in `docs/zeroContracts/Design.md` ("Prices and closed markets"); this file is the evidence, cited by ID (KEEP-2 to KEEP-22; KEEP-1 is in `docs/evaluation/Contracts.md`).*

The BSC keeper was extended to the v2 spec and run end to end on an anvil fork of Arbitrum (block 523,123,000). The fork has the real xStocks tokens and V2 wrappers and a freshly deployed `PoppieEulerOracle`. The production KMS signer code runs against a local KMS stand-in. Data Streams, Alpha Vantage, Polygon and Backed's API are fakes that speak each vendor's wire format, since there are no vendor credentials. Backed's keys are impersonated to schedule multipliers, pause and turn on fees. How to run it is in oracleSystem `V2.md`.

| KEEP-2 | Issue (BSC) | **The BSC keeper's anvil suite fails at `3e5092e`, before any v2 change.** Its oracle fixture is an older contract (`int256` prices, 7-field struct). The keeper decodes the deployed packed struct, so decoding fails ("decode asset state: unexpected EOF"). The harness also drives Pyth, while production uses Data Streams. So the keeper's end-to-end path has no passing test against the deployed contract. The suite is excluded from v2 runs, not changed. | KEEP-3 | **Likely issue (BSC)** | **The BSC Alpha Vantage cross-check may compare nothing.** It parses a `price` field. | KEEP-6 | Issue: scale, **fixed in the prototype** | **Backed's multiplier API: exact, but one slow call per name.** On-chain and API multipliers agreed exactly (to 1e-12) on all 53 names checked, and again on a real dividend (KEEP-19). Latency per call: median 1.0 s, 90th percentile 3.6 s, max 4.9 s. The rate limit header shows 1,000 calls per window (window length unknown). Calling it for every name would take 60–220 s at 500 names, past the 110 s run timeout. **The keeper now calls it only for a name with a pending schedule on-chain, a multiplier different from the last accepted push, or no stored multiplier.** 71 names: first run 36 s (every name checked), then 6 s with no multiplier API calls. With the API down, unchanged names keep pricing; changed or pending names are skipped. After keeper state is lost, every name needs the API again. `activationDateTime` is an ISO 8601 string with a UTC offset while a change is pending, and `0` otherwise. A bulk endpoint would still help bootstrap | `TestLiveArbitrum`, `TestIssuerAPIOnlyOnChange`, `TestIssuerAPIDown`, `TestScaleAllCovered`; shadow recording 2026-11-11 |
| KEEP-7 | Issue, design | **The multiplier gate needs keeper state.** "Any change must match a corporate action" needs the multiplier used at the last accepted push. On-chain history is missing on 87% of tokens (KEEP-5), and Backed's API shows the reason only while a change is pending. So v2 stores, per name, the last accepted multiplier, the schedules seen while pending (with reason) and the skip streak. If state is lost, the first run accepts the current multiplier, so a rogue change during the loss would pass; one ERROR per run lists the names accepted this way. Production needs the halt latch's GCS backend, with conditional writes and backups (POP-73) | `pkg/keeperstate` (`TestFileRoundTrip`); `TestCleanPush` (bootstrap alert); `TestRogueHalving` |
| KEEP-8 | Issue (BSC), fixed in v2 | **Per-name isolation.** In the BSC keeper, one asset's multiplier fetch error aborts the whole run (`push/run.go:472-475`). Three such runs trip the halt latch for every asset. Data Streams fetch errors are already per feed. In v2, any per-name failure skips only that name. Only run-level failures fail the run and count toward the latch: RPC, signer, no chunk landing, and also keeper-address mismatch, keeper balance below minimum, unreadable keeper state and an undecodable sequencer feed. With Backed's API down, unchanged names keep pricing; names with a pending or changed multiplier are skipped, and page on the second consecutive skip. The run succeeds and the latch is untouched. A chunk whose transaction fails skips only its names | `TestIssuerAPIDown`, `TestFailedChunkSkipsOnlyItsNames` |
| KEEP-9 | Info, tuning | **KMS client retries hide short outages and stretch long ones.** The KMS Go client retries `Unavailable` and `DeadlineExceeded` itself (100 ms backoff, ×1.3, 60 s per call). A blip is invisible. An outage blocks a single signature for up to 60 s, most of a 110 s run. The run then fails as `signer`, and three such runs trip the latch. Recommend a 15 s timeout per signature so runs fail fast and clearly (POP-73). The KMS stand-in returns high-S signatures half the time; the signer's low-S and recovery-id handling passed 60 signatures | `TestGCPKMSSignerFaults`, `TestGCPKMSSignerAgainstEmulator`, `TestKMSOutage` |
| KEEP-10 | Keeper rule, confirmed | **Splits: only the multiplier gate can catch the gap.** At the ex-date open, Data Streams and the second sources switch to split-adjusted prices together, so the stock-price gate passes. The multiplier switches only when Backed activates it, hours later (14:00 UTC for SOXX). v2 skips a name while a `Split` or `ReverseSplit` is pending. After activation, it rejects the change until the calendar lists it, then pushes a 0% move. A 1:10 reverse split is also continuous, with no `adminSetPrice`. The name is stale from scheduling until the calendar entry exists: about Backed's notice (normally 2 h) plus calendar latency | `TestSplit`, `TestReverseSplitNeedsNoAdmin` |
| KEEP-11 | Keeper rule, confirmed | **HONx replay.** An instant ×0.5 that Backed's API also reports is caught only by the calendar check. The name is skipped and paged on every run, and its stored price is unchanged. Pushing resumes on its own only if Backed restores exactly the last accepted multiplier. The real HONx reset landed 2.44% lower, so in practice the reset needs a manual approval entry in the calendar file (type `approval` with the ratio) before the name prices again | `TestRogueHalving`; `docs/issuerResearch/HONx-Multiplier-Incident.md` |
| KEEP-12 | Keeper rule, confirmed | **Schedule checks and expected skips.** The keeper skips and pages when an on-chain schedule is missing from the API, or when an override changes it before the API catches up. It skips without paging while a split is pending, and when activation is within 5 min of the read block, because the push could land after the multiplier changes. Oracle state and multipliers are both read at one pinned block. These expected skips, closed markets and sessions no second source covers reset the skip streak, so repeated ones never page. A dividend listed in the calendar without a ratio is accepted up to +5%. Backed's reason is stored against the exact on-chain pending value, once the on-chain and API activation times agree | `TestScheduleChecks`, `TestSplit`, `pkg/gates` tests |
| KEEP-13 | Not an issue | **Management fee.** `getCurrentMultiplier()` applies the fee per elapsed period inside the view, so `convertToAssets` decays with no transfer. On the fork, with Backed's owner setting 0.1% per week, the wrapper rate dropped after one period. The gate attributes exact (1 − fee)^k steps to fees | `TestFeeAccrual` |
| KEEP-14 | **Open: biggest unresolved dependency** (POP-85) | **The corporate-action calendar.** v2 reads a reviewed JSON file, which also serves as the manual approval path. Every reinvested dividend changes the multiplier, typically by 0.3–2.5% a quarter per name. Without a calendar entry, the name stops pricing. At 100–500 names, that is hundreds of entries a quarter, so a market-data source of splits and dividends is needed (Polygon and Alpha Vantage both have endpoints; untested without keys). Calendar entries must give the dividend ratio net of withholding (KEEP-19); the keeper matches the ratio it is given and applies no withholding itself. If a management fee is on, up to 8 fee periods are divided out before matching. Also to set: the bound for dividends with no ratio, now 5% | `pkg/corpactions`, `pkg/gates` |
| KEEP-15 | Issue (BSC), fixed in v2 | **Data Streams fetching.** The BSC keeper fetches feeds one at a time, 3 per asset, which does not fit 100–500 names. v2 fetches 8 at a time. The BSC keeper also picks the report schema from blob length, so any 9-word schema would be decoded as v8 and read the wrong word. v2 takes the schema from the feed ID prefix (`0x0008` = v8, `0x000b` = v11). 8 listed names use v8 feeds | `pkg/chainlink`; `TestScaleAllCovered` |
| KEEP-16 | Info | **Scale and cost (71 names).** Run time is 36 s, with fake Data Streams at 150 ms and Backed at 1 s per call, 8 in flight; Backed calls dominate. The push is one transaction: 1.04M L2 gas (14.7k per asset on the first push after seeding; A7 measured 7.1k in steady state) and 4.7 KB of calldata. At 2026-11-10 prices (L2 0.02 gwei; L1 1.47e7 wei per calldata byte from `ArbGasInfo`) that is about 0.00009 ETH per run. Chunks of 3 produce 3 transactions; a failed chunk skips only its names | `TestScaleAllCovered`, `TestChunking`, `TestFailedChunkSkipsOnlyItsNames`; `ArbGasInfo.getPricesInWei` |
| KEEP-17 | Keeper rule, confirmed | **Sequencer gate.** No push while Chainlink's Arbitrum uptime feed (`0xFdB6…697D`) reports down, or within the grace period after it comes back. A round with `startedAt = 0` counts as not up. Downtime logs at ERROR. The grace period is set to 20 min as a placeholder (POP-73) | `TestSequencerGate`, `TestSequencerRoundNotStarted` |
| KEEP-18 | Open (POP-84) | **Second sources by session.** The fakes quote overnight; real Alpha Vantage covers 04:00–20:00 ET, and Polygon's coverage is untested. A shadow collector (`scripts/v2/shadow`) recorded Yahoo and Nasdaq (research only, not licensed) for the 71 names every 5 min from 2026-11-11 00:19 to 2026-11-12 19:37 UTC. Their agreement (\|Yahoo − Nasdaq\| / Nasdaq): regular hours median 0%, 99th percentile 0.17%, max 0.82% (7,601 pairs); extended hours median 0.05%, 99th percentile 1.4%, max 6.6% (6,361); overnight unusable, since neither quotes overnight. So a 2% regular-hours tolerance looks safe, while a flat 3% in extended hours would block thin names on vendor noise: extended-hours tolerances should depend on the name's liquidity. The prototype uses 2% regular and 3% extended as placeholders; calibrate with the licensed vendors. **Overnight is not priced**: no configured source quotes it, so the gate reports the session as uncovered, a planned skip that never pages (`TestSecondSources`). Outside regular hours an Alpha Vantage quote counts only if `extended_hours_quote` is present; the previous `close` is never used (`TestAlphaVantageSessionFields`). **The raw recording was lost** (it was kept in a temporary directory); only these summary figures remain. The collector was restarted on 2026-11-13 and writes outside `/tmp` | `scripts/v2/shadow` |
| KEEP-19 | Info, design | **A real dividend, end to end.** AAPLx's multiplier rose 0.053% (1.0032690 → 1.0038023) and STRCx's 0.040%. Both were scheduled on-chain and visible in Backed's API by 21:52 UTC on 2026-11-11, reason `Dividend`, and activated at 01:30 UTC on 11-12, in the overnight session. Notice was at least 3.6 h (the collector polled every 30 min). The API and the chain agreed on the new value and on the activation time to the second. Lessons: (1) without a calendar entry, both names stop pricing at activation, every quarter, for every dividend payer; (2) the step matches AAPL's dividend net of 30% US withholding, so calendar matching must use the net amount: the gross amount misses the 0.1% ratio tolerance, and the change passes today only through the 5% bound for dividends without a ratio; (3) activations land overnight, so the calendar entry must exist before the next priced session | Shadow recording; `newMultiplier`, `newMultiplierActivationTime` |
| KEEP-20 | Keeper rule, confirmed | **Wind-down signals.** A listed name losing `Issuance` from `allowedOperations`, or marked trading-halted, in Backed's API pages but does not stop pricing; the wind-down itself is an `MS_OPS` decision (`docs/zeroContracts/Design.md`, "Corporate actions", item 5). It is checked before the session test, so it also alerts while the market is closed, and only when `allowedOperations` is present, so a schema change cannot flag every name. Backed's status list is paged in one pass of ~15 calls and cached for 5 min | `TestWindDownSignal`, `TestWindDown` |
| KEEP-21 | Fixed in v2 (review, 2026-11-16) | **Review of the prototype against the zero-contract design.** Fixed and tested: (1) overnight would have paged every night, since no second source quotes it; it is now a planned skip; (2) Alpha Vantage's previous close could pass as a fresh extended-hours quote; (3) a name dropped by an on-chain revert never paged; it now logs at ERROR and counts toward the streak; (4) the bootstrap alert was an INFO log, so it never alerted; (5) a management-fee step after activation could hide an `Administrative` reason; any `Administrative` schedule activated since the last push is now rejected; (6) a missing `allowedOperations` field would flag every name for wind-down; (7) the sequencer gate accepted `startedAt = 0` and logged downtime at WARN; (8) the off-chain guard check ignored anchor rotation and could drop a name the contract accepts (`CheckGuardsAt`, v2 only); (9) Polygon was fetched one ticker at a time and the second sources in sequence, too slow for 500 names; (10) `POPPIE_WIRING=emu` and `POPPIE_KMS_ENDPOINT` (KMS without auth or TLS) were accepted with `POPPIE_ENV=prod`; both are now refused. The v2 retry after a reverted batch never ran, see KEEP-22 | oracleSystem `81852ad`; `TestBatchRevertDropsAndPages`, `TestFailedChunkSkipsOnlyItsNames`, `TestSequencerRoundNotStarted`, `TestSecondSources`, `TestCleanPush`; unit tests in `pkg/gates`, `pkg/quotes`, `pkg/xstocks`, `pkg/oracle`, `pkg/keeperstate`, `pkg/signer`, `pkg/pushv2` |
| KEEP-22 | **Likely issue (BSC); fixed in v2** | **The single retry after a reverted batch (A1) does not run for guard reverts.** The writer classifies the oracle's breaker, cumulative-cap and not-configured errors as `circuit_breaker` or `not_configured`, but the retry only runs for `tx_revert`. The address parser also expects `0x<selector><word>`, while anvil reports `custom error 0x249ffe6a: <word>`. So the whole push fails instead. On BSC this is rare, because the off-chain guard check drops failing names first, but one failure still blocks every name for that run. v2 now retries on all three kinds and reads the address from the JSON-RPC error data or either text format. `pkg/push` is unchanged | `push/run.go:567-579`; `oracle/writer.go` `classifyEstimateError`; `TestBatchRevertDropsAndPages` (failed before the fix); `TestExtractRevertAddress` |

Other scenarios that pass: Backed's API called only on change (`TestIssuerAPIOnlyOnChange`); a split and fee periods in the same window still matching the calendar (`pkg/gates`); a clean push of 9 names, including COSTx on the older implementation; issuer pauses (token or wrapper paused: the name is skipped, the oracle is not paused, and the second consecutive skip pages); second sources (one disagreeing by 5% blocks and pages; one stale with the other agreeing pushes; both down fails closed, pages and leaves the latch alone); market closed (no push and no page); and the real `cmd/pushv2-emu` binary through fx wiring. Test files: oracleSystem `test/arbfork/*_test.go`, and unit tests in `pkg/gates`, `pkg/quotes`, `pkg/xstocks`, `pkg/oracle`, `pkg/keeperstate`, `pkg/signer` and `pkg/pushv2`.

The fork suite starts one anvil per run and gives each test a snapshot that is reverted afterwards (21 tests, about 4 minutes). It needs an archive RPC for the pinned block; with the public Arbitrum RPC, set `ARB_FORK_BLOCK` to a recent block. On 2026-11-16 all 21 passed that way except `TestScaleAllCovered`, which met a real pending STRCx dividend that the fake Backed API does not mirror (an artefact of the recent block). Starting anvil was the flaky step in this environment: DNS for the RPC host sometimes resolved to an unreachable address.
